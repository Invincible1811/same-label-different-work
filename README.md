# Same Label, Different Work: Roles, Resolution Time and Topics of GitHub Issues Attributed to Thirteen AI Coding Agents

Replication package for a mining-software-repositories study of 4,952 GitHub issues that a
public dataset attributes to 13 AI coding agents (COIS-5210H, Individual Assignment 1, RQ Set 5).
The report is [`report/main.pdf`](report/main.pdf); its main finding is that the agent label
covers different kinds of work, because agents write, trigger or are merely mentioned in issues.

| RQ | Question | Method |
|----|----------|--------|
| RQ1 | How do issues attributed to different agents differ in volume, state and labelling? | Rates with Wilson CIs; permutation χ², Cramér's V; adjusted residuals |
| RQ2 | Does time-to-close differ across agents, and by how much? | Kruskal–Wallis, ε², Dunn/Holm, Cliff's δ; Kaplan–Meier, log-rank |
| RQ3 | Which topics do the issues raise, and does that differ by agent? | Ensemble LDA (seed-reproducible topics), triangulated with BERTopic |

## Reproduce everything

The course dataset is not redistributed. With Python 3.11:

```bash
# 1. put issues.csv, issue_labels.csv, issue_comments.csv, issue_assignees.csv in data/raw/
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m nltk.downloader wordnet omw-1.4
bash run_all.sh          # about 1-1.5 hours; runs every step, then every check
```

`run_all.sh` stops at the first failure. Every random step uses a fixed seed, so a rerun on
the same data gives byte-identical tables; compare them with the SHA-256 fingerprints in
[`results/MANIFEST.csv`](results/MANIFEST.csv), or run
`python checks/check_07_replication.py <reference results folder>`.

## Pipeline

| Step | Script | What it does |
|------|--------|--------------|
| 1 | `src/01_clean.py` | Cleaning decisions D1–D15 (5,000 → 4,952 issues), each logged with counts |
| 2 | `src/02_rq1.py` | RQ1 tables, tests, findings and figures |
| 3 | `src/03_rq2.py` | RQ2 tests, survival analysis, sensitivity checks S1–S4, figures |
| 4 | `src/04_rq3_preprocess.py` | RQ3 corpus: English issues, cleaned text, tokens |
| 5 | `src/05_rq3_select.py` | Single-LDA model selection and seed stability |
| 6 | `src/06_rq3_ensemble.py` | Two independent Ensemble-LDA runs; headline and fine topic levels |
| 7 | `src/07_rq3_topics.py` | Topics, agent shares, associations, stability, topics × time-to-close |
| 8 | `src/08_rq3_embed.py` | Sentence embeddings for BERTopic (downloads a pinned model once) |
| 9 | `src/09_rq3_bertopic.py` | BERTopic triangulation of the RQ3 conclusions |
| 10 | `src/10_validation.py` | Manual validation: blind random samples, the answer workbook (created once), and the scores |
| 11 | `src/11_report_assets.py` | Every number and table in the report, as LaTeX macros |
| 12 | `src/12_manifest.py` | `results/MANIFEST.csv`: every output, its producer and SHA-256 |

Shared code: `src/config.py` (all constants, seeds, thresholds and rules),
`src/stats_utils.py` (statistics), `src/rq3_common.py` (RQ3 corpus and model),
`src/plotstyle.py` (figure style).

## Notes for replicators

The results were produced on macOS (Apple silicon) with Python 3.11.8. A clean virtual
environment built from `requirements.txt` reproduced the tables of steps 1 to 3; one table
differed in the sixth significant digit (Shapiro–Wilk p-values, because the SciPy builds
differ), and figure images differed only in font rendering. `check_07_replication.py`
tolerates both.

Two technical points may save a replicator some time. `09_rq3_bertopic.py` sets
`OMP_NUM_THREADS=1` itself, because PyTorch and scikit-learn ship different OpenMP runtimes
that crash together on macOS. And in gensim 4.3 the setting `eta="auto"` has no effect, so the
prior grid uses fixed values; topic inference on the Ensemble-LDA model is seeded explicitly,
because gensim builds that model without a seed.

## Use of generative AI

The researcher used Claude (Anthropic) as an assistant for the literature search, for writing and
checking the code scripts, and for drafting and editing the text. All study decisions and the
manual validation were the researcher's own; every reported number is generated from the result
files and independently re-checked, and the researcher reviewed and is responsible for the entire
content.
