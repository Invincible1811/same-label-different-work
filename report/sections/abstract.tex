AI coding agents no longer only write code. They open, trigger and appear in GitHub issues, yet most empirical work on them studies their pull requests. This study compares \NIssues{} GitHub issues from \NRepos{} repositories that are attributed to \NAgents{} AI coding agents, and asks how the issues differ in volume, state and labelling, in time-to-close, and in topic. The agents differ most in \emph{how} an issue is linked to them (Cram\'er's V = \VAttribution, large): \OwnBotShareCoderabbit\% of CodeRabbit and \OwnBotShareDevin\% of Devin issues were written by the agent's own bot, while for Claude Code, Sweep and Jules almost none were. Within the same agent, bot-written issues are closed 18--24 percentage points less often than the others, and issue age does not explain the gap. Labels mislead as well: most labelled Sweep issues carry only a label that invokes the agent. Time-to-close differs across agents with a medium effect (\(\varepsilon^2 = \KWeps\)), but ranking agents by their closed issues alone disagrees with a survival analysis that counts the issues still open (Spearman \(\rho = \RankRho\)). Because single LDA runs were not reproducible on this corpus, the topics are taken from Ensemble LDA, graded by their stability and confirmed with BERTopic. Under both models, CodeRabbit's issues lean strongly towards code-level fixes, and its bot-written issues are mostly follow-ups from pull-request reviews. The label ``AI agent'' thus covers distinct kinds of work, and studies that compare agents should separate these roles and account for open issues.
